AI Investment OS · LLM Session Architecture

每一檔股票，都是一個獨立的分析腦。

StockPilot AI 把股票研究拆成可隔離的 session，讓 2308 與 2408 不共用對話污染；同時把使用者投資風格做成 Strategy Profile，讓同一套分析邏輯能服務不同風格的投資人。

Architecture Focus

這一版系統規格的重心，已從「股票分析概念」推進到「可實作的 LLM 後端架構」。

Analysis Unit
User + Strategy + Symbol
分析單位不是全站聊天室，而是綁定使用者、策略、股票與週期的 session。
Prompt Inputs
Rulebook + Memory + Data
模型輸入會組合系統規則、策略設定、個股記憶與最新資料。
Output Style
Bull / Base / Bear
未來趨勢不用保證式預測，而是改用情境研判與失效條件。
Auditability
Snapshot First
每次分析保留快照、資料新鮮度、模型版本與策略版本。

Isolated Stock Sessions

不同股票預設不能互相影響。這不是 UI 細節，而是整個系統的資料與 prompt 邊界。

Session Key
User + Strategy + Symbol + Timeframe
同一個使用者看不同股票，會進不同的分析脈絡。
Memory Layer
Summary + Structured Facts
把可追溯內容壓成可控 token，不回放全部歷史。
Live Query
One Stock at a Time
盤中詢問與研究模式都綁定到單一股票 session。
1
建立或重用 session
若 `user + strategy + symbol + timeframe` 相同且仍 active，系統重用原本 session。
2
抓最新市場資料
價格、新聞、籌碼與大盤資料依照新鮮度規則補齊。
3
組 prompt 並呼叫 LLM
只附這檔股票的記憶與資料，避免與其他標的互相污染。

Strategy Profiles

同一套模型，不應只輸出一種投資風格。策略偏好要成為系統一級公民。

Risk Tolerance
Low / Medium / High
影響建議語氣、進場保守程度與風險提醒強度。
Entry Preference
Pullback or Momentum
可設定是否接受追高、是否偏好拉回承接。
Position Rules
Size + Stop + Take Profit
讓建議能落到倉位與停利停損，不只停在描述。
Version Control
Historical Trace
每次分析都記住當時用哪個策略版本。

Output Contract

無論使用者喜歡保守或積極，系統都仍然要守住分析底線。

A
事實與推論分開
不能把新聞、數據、假設與研判混在一起說。
B
策略不覆蓋風控
即使用戶接受追高，系統也必須保留追高風險提醒。
C
情境式預測
用 Bull / Base / Bear 情境表達未來走勢，而不是保證結論。

Backend Architecture

後端拆分以 orchestration 為中心，讓 session、strategy、market data、memory 各自負責自己的邊界。

API Gateway
Auth + Entry
對前端統一提供 API，處理驗證與流量控制。
Session Service
Session Lifecycle
管理獨立 stock session、message 與狀態。
Strategy Service
User Profiles
管理使用者策略、版本與預設策略。
Analysis Orchestrator
Prompt + LLM + Snapshot
載入資料與記憶，呼叫模型並寫回分析快照。
1
Market Data Service
正規化股價、籌碼、新聞、財報與大盤資料，並管理資料新鮮度。
2
Memory Service
負責 session summary、結構化記憶與摘要壓縮，不讓 token 無限膨脹。
3
Worker Queue
收盤後重分析、批次 watchlist 掃描、異常事件通知都應走非同步。
